# Models

`PYTHONPATH=src python -m dam_outlook.forecast` が `data/normalized/` から予測を出し、`data/forecasts/<YYYY>/<MM>/<発行時刻>__<model>-v<version>.json` に1件1ファイルで保存する。ファイルは排他作成で、後から編集しない。各ファイルに発行時刻（`issued_at`）、基準日（`base_date`、最新の観測日）、モデル名と版、使った入力の値すべて（`inputs`）とそのハッシュ、パラメータ、予測系列を入れる。入力が前回と同じなら発行しない（週末など）。どのモデルも、同じ実行で無降雨の基準予測を必ず一緒に出す。

対象は9ダム合計の貯水量（m³）。貯水率は基準日の利水容量で換算する（利水容量は季節で変わる。[tables.md](tables.md)）。予測期間は基準日の翌日から28日。

以下はすべてモデルの出力であり、公表値ではない。

## baseline_norain v1（基準）

雨が降らないと仮定した単純な外挿。直近14日の日々の増減（浄水日報の増減水量。無ければ前日との差）のうち、雨のなかった日（日報で全ダム降水なし。日報が無い日はアメダス3地点の9時〜9時降水量がすべて0）の中央値を1日の減少量とし、0以下に抑える。雨のない日が3日未満なら全日の中央値。検証の比較基準として使う。

## scenario_jma_tercile v1（2026-10-25〜）

過去の同じ季節の雨を、気象庁1か月予報の降水量3階級確率（九州北部）で重み付けしたモンテカルロ（2000本）。

1. **貯水量の増減のモデル**: `増減(t) = 水準 + Σ_{j=0..3} q_j × 雨(t−j) + g × 遅い流入(t)`。
   - 雨はアメダス3地点（福岡・前原・太宰府）の暦日降水量の平均。
   - 遅い流入は、4日以上前の雨を時定数10日で指数減衰させた和（`slow(t) = Σ_{j≥4} 雨(t−j)·e^{−(j−4)/10}/10`）。
   - 係数 q_j・g と定数は、基準日までの全履歴（報告資料のグラフの読み取り値と公表値、2022-04〜）から最小二乗で推定する。前日の貯水量が利水容量の93%を超える日は、あふれて流入が貯まらないので除く。
2. **水準**: 直近28日の残差の中央値に定数を足したもの。取水制限・節水・導水の変化は、ここに表れる分だけ入る。残差が7日未満なら定数だけを使う。
3. **雨のシナリオ**: 基準日の年以外の各年（2006〜）で、同じ月日の前後30日を起点とする28日間の実際の雨（`analog_windows`、約1,200通り）。
   - 28日間の合計で、少ない・平年並・多いの3つに等分する。
   - 1か月予報の確率を各区分の本数で割って重みにする。1か月予報が無ければ等確率。
   - 雨の量の予想値は作らず、ページにも出さない。
4. **水準のゆらぎ**: シミュレーションごとに N(0, σ) を水準に足す。σ は、履歴の「次の28日の残差の平均 − 直近28日の残差の中央値」の標準偏差（2026-10 時点で約14万m³/日）。
5. 基準日より後でも観測がある日は観測した雨を使う。貯水量は0〜利水容量に収める。

`inputs` には、学習データのハッシュ（`training_sha256`）、基準日の遅い流入の状態、直近の観測雨量、シナリオの雨のハッシュと区分ごとの本数、1か月予報を入れる。学習データとシナリオは `data/normalized/` の表から作り直せる。推定した係数・σ・水準は `params` に入る。

### 選んだ根拠（後ろ向きの答え合わせ）

`python -m dam_outlook.hindcast` が、2023-08 から 2026-09 までの毎週の基準日（154日）で、その日までのデータだけを使って予測し、実績と比べる（`data/verification/hindcast.csv`）。

- 基準日の年の雨は使わない。過去の1か月予報は残っていないので、3階級は等確率にする。
- 2026-10-25 時点の結果（28日先）:
  - 基準予測: 平均絶対誤差 417万m³。
  - v1: 中央値の平均絶対誤差 461万m³、CRPS（近似）280万m³。実績が10〜90%の範囲に入った割合は80%。
- 中央値だけを見ると基準予測より外れる。この期間は渇水で、雨が平年より少なかったため。確率つきの見通しとしては、CRPS で基準予測より約3割良い。

作業用の分析では、次も比べた。
- **v0 と同じ考え方**（当日の雨だけ、直近60日の雨の日から k を推定）を同じ雨のシナリオで動かした場合: CRPS 364万m³、範囲に入った割合18%。v0 の見通しの幅は狭すぎた。
- **将来の雨を観測値にした場合**（雨以外の部分だけの比較）: 28日先の平均絶対誤差は、基準予測 428万m³、v0 の考え方 367万m³、v1 300万m³。
- **遅い流入の時定数**: 10日（20日・40日より良い）。
- **雨のシナリオの年数**: 4年分より20年分のほうが少し良い。

既知の弱点:
- 報告資料のグラフの読み取り値には、1日あたり2万m³ほどの誤差がある。
- 利水容量の季節変化（6/1・10/21）を、予測期間の中では反映していない。
- 取水制限の強化・解除は、水準のゆらぎとしてしか扱っていない。
- 1か月予報の確率を、28日間の合計の3区分にそのまま当てている（気象庁の階級は平年値に対する区分で、ここでの区分とは定義が違う）。

## scenario_jma_tercile v0（2026-10-23〜10-25、発行済みの予測は残す）

気象庁1か月予報の降水量3階級確率をシナリオの重みにしたモンテカルロ（2000本）。期間全体の階級を確率どおりに1つ引き、週ごとの降水量を週間予報の福岡の7日間降水量の平年並の範囲から引いて週の中で均等に配る。1日ごとに `貯水量 += 減少量 + k × 降水量`。減少量は基準予測の日々の増減のブートストラップ平均、k は直近60日の雨の日（アメダス3地点の9時〜9時平均 5mm 以上）の `(増減 − 減少量) / 降水量` の中央値（10/25 時点で1日分、16,805 m³/mm）。雨の当日にしか流入を入れず、後ろ向きの答え合わせでは見通しの幅が狭すぎた。
